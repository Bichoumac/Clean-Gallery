# ADR 0018 — Perceptual hashes from grayscale thumbnails, computed in Dart

Where the pixels for similar photo detection come from, and where the hashes are computed.

Last updated: 2026-10-27 — Milestone M4

- **Status**: Accepted
- **Date**: 2026-10-27

## Context

The brief: "Similar photos: 64-bit dHash and pHash, Hamming distance", with the engine "in an isolate", working "on thumbnails whenever possible; never bulk-load full-size originals". Hashing needs the pixels of every photo once. Dart cannot decode JPEG or HEIC without a package, and decoding originals would be slow and memory-hungry.

## Decision

- **Pixels**: a native method `grayThumbnails` asks MediaStore's thumbnail cache (`ContentResolver.loadThumbnail`, the cache the grid already uses) for each photo at most 128 × 128 pixels and returns one brightness byte per pixel (luma, `0.299 R + 0.587 G + 0.114 B`). About 12 KB per photo crosses the channel. It runs on the hashing thread, after any SHA-256 work, 16 photos per call (40 at first; lowered on 2026-10-27 so the scan can pause quickly for the viewer) ([MediaIndex.kt](../../android/app/src/main/kotlin/com/bichoumac/clean_gallery/MediaIndex.kt)).
- **Hashes in pure Dart** ([perceptual_hash.dart](../../lib/analysis/perceptual_hash.dart)), in an isolate (`Isolate.run`), so they are testable without a device and identical on every platform:
  - **dHash**: area-average resize to 9 × 8; bit = pixel darker than its right neighbour.
  - **pHash**: area-average resize to 32 × 32, 2D DCT-II, the 8 × 8 lowest frequencies without the DC row and column, bit = coefficient above their median.
- **Stored** in `assets.d_hash` and `assets.p_hash` (64-bit signed integers), with `analysis_version = 1`. A photo without a readable thumbnail is marked analysed without hashes, so it is not retried until its file changes (like unreadable files for SHA-256, [ADR 0017](0017-exact-duplicates-sha256.md)).
- **Reset** when the file changes (modification date or size), at **Analyze the library again**, and for every photo when `analysisVersion` is bumped.

## Alternatives considered

- **Hashing in Kotlin**: faster, but the algorithm would be untestable in Dart unit tests and duplicated for iOS later. A DCT on 32 × 32 is cheap enough in Dart.
- **Decoding in Dart with the `image` package**: needs the file bytes over the channel (megabytes per photo) and no HEIC support.
- **RGBA thumbnails through the existing `thumbnail` method**: four times the data, and that loader serves the grid on a last-in-first-out queue that drops old requests; the scan must not compete with scrolling.

## Consequences

- No new runtime dependency; the `image` package is a dev dependency only, used to build the synthetic test photo set ([photo_set.dart](../../test/analysis/photo_set.dart)).
- Hashes depend on the platform's thumbnail rendering. A recompressed or resized copy gets a thumbnail that is nearly the same, which is what similarity needs; tests check that recompression, resizing and brightness stay within the strict threshold.
- A thumbnail is generated by MediaStore on first request if it is not cached yet: the first analysis of a large library takes minutes, in the background, saved after each call.
- Video near-duplicates (brief: same duration, resolution and close dates) are not part of M4.
